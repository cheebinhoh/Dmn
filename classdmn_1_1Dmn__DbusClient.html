Detailed Description

Generic, typed client for calling services on a D-Bus daemon.

Architecture

Dmn has two D-Bus integration paths. They share the libdbus runtime, but the byte-signal endpoints do not use this generic method-call client:

* Bluetooth / typed service API
* Application
*   -> Dmn_BluezClient / Dmn_BluezGattClient
*        -> Dmn_DbusClient + Dmn_DbusValue
*             -> private codec -> libdbus -> bus daemon -> org.bluez
*
* DMesg / byte-signal transport
* Application -> Dmn_DMesgDbus -> Dmn_DMesgNet
*                  -> Dmn_DbusInput / Dmn_DbusOutput
*                       -> libdbus -> bus daemon
*

The BlueZ clients use typed method calls, properties, and signal subscriptions through this class; they interpret generic D-Bus values as Bluetooth state. In the DMesg path, separate Dmn_DbusInput and Dmn_DbusOutput endpoints carry byte-array signals through Dmn_Io. Those endpoints own their own connections and workers and do not call Dmn_DbusClient. Both paths use the process-wide libdbus initialization provided by dmn-dbus.

This library is a D-Bus client, not a bus daemon or a D-Bus service. The selected bus daemon must already be running. A service process connects to that same bus, owns the destination name, and exports the requested methods and objects. A client sends a method call through its dedicated private connection; the bus daemon routes it to the named service and routes the reply back. Signal subscriptions install match rules on the bus daemon. A method call receives either a method-return message or an error message; a signal is a one-way announcement without a method reply. This client uses one bidirectional connection: caller threads submit pending calls, while its dispatch worker reads and dispatches incoming replies. Completion decodes the result and fulfills the call future; call() waits on the caller thread, while callAsync() exposes a Dmn_DbusCall handle. The four D-Bus message types and full request/reply flow are described in docs/specs/dbus-client-spec.md.

All supported connection choices use a bus daemon. In Address mode, the supplied address is opened and registered as a bus connection. This client does not support direct peer-to-peer D-Bus connections, where a client connects directly to a service process without bus routing.

Dmn_DbusValue is the owned, type-preserving message-body model. The private codec translates values to and from libdbus messages, so callers do not manage DBusMessage, DBusMessageIter, or borrowed message memory. This layer provides generic D-Bus operations; service-specific meaning belongs in a higher-level client such as Dmn_BluezClient.

Concurrency and lifetime

Each Dmn_DbusClient owns one connection, one I/O/dispatch worker, and one serial signal-callback worker. Method replies are completed by the dispatch worker. Signal callbacks receive owned values on the callback worker, not on the dispatch worker. Signal callback deliveries and serialized message sizes are bounded by Dmn_DbusClientLimits; overload is reflected in status().

The synchronous call() helper waits on its calling thread and must not be called from the dispatch worker. Do not call it from a signal callback either: that would block the serial callback worker and delay all later callbacks. User callbacks must return promptly and must not destroy the client; concurrent destruction with public calls is unsupported. shutdown() stops new admission, resolves outstanding calls with a shutdown result, joins the workers, and releases the connection. The client does not automatically reconnect after a terminal disconnect. The detailed generic-client and BlueZ contract is in docs/specs/dbus-client-spec.md; the byte-signal transport contract is in docs/specs/dmesg-dbus-spec.md.

Bus selection and security

Dmn_DbusClientConfig selects the standard session bus, the standard system bus, or an explicit bus-daemon address. The explicit address may identify either standard bus or a separately started private bus instance. In every case this client owns a dedicated private connection to that bus; it does not start or manage the daemon. A private bus is a separate daemon instance, not another name for the client's private connection. This client does not support direct peer-to-peer connections and never falls back to another bus. Successful connection does not imply permission to call every service: the bus daemon's policy and the target service's authorization still apply.

Typical use:

Dmn_DbusClient client;
auto reply = client.call("org.example.Service", "/org/example/Object",
"org.example.Interface", "GetValue");
if (reply) {
// Inspect the owned Dmn_DbusValue reply arguments.
}
