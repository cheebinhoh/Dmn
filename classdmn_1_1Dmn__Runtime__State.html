Detailed Description

A runtime-managed state machine instance.

Dmn_Runtime_State subclasses Dmn_State and adds asynchronous runtime ownership semantics: a client obtains a shared_ptr handle from the manager, configures state functors using the inherited Dmn_State API or the runtime-aware setRuntimeStateFnc() helper, then calls run() to schedule execution on the global runtime thread.

Lifecycle

A state is configured, submitted once, and then completes, fails, or is cancelled. Cancellation is cooperative: it prevents subsequent state steps but does not interrupt a functor already executing. Completion is published through a std::shared_future<void>, which supports multiple waiters.

The inherited Dmn_State configuration API remains the client-facing way to install state functors before submission. After a successful run, external calls to Dmn_State::setStateFnc, Dmn_State::setNext, and Dmn_State::setEnd throw std::logic_error. Manager-driven execution still permits state callbacks to call setNext or setEnd from inside the currently executing runtime step. External runNext calls are rejected; only the manager may advance the machine.

For callbacks that need runtime-only APIs such as isCancelled(), use setRuntimeStateFnc(). It adapts a callback that takes Dmn_Runtime_State & into the underlying Dmn_State callback storage while preserving the base API for compatibility.

◆ cancel()

void dmn::Dmn_Runtime_State::cancel ( )

Request cooperative cancellation of this state.

The cancellation is idempotent and thread-safe. It does NOT preempt a currently-running functor. A callback that needs cooperative early exit should prefer setRuntimeStateFnc() so it can query isCancelled() directly on its Dmn_Runtime_State & parameter. The runtime job must check isCancelled() and call setEnd() prior to invoking runNext() if cancellation is set.

A state cancelled before submission becomes terminal immediately. A submitted state becomes terminal when the runtime observes the request.
