◆ cancellation_requested

std::function<bool()> dmn::Dmn_AncsMonitorConfig::cancellation_requested {}

Optional cooperative cancellation check for startup.

Checked between setup stages. Calls already in progress remain bounded by their configured timeout; if cancellation arrives during ANCS startup, the newly started session is stopped before start() returns. The callback must return promptly and must not throw.

◆ progress_handler

Dmn_AncsMonitorProgressHandler dmn::Dmn_AncsMonitorConfig::progress_handler {}

Optional callback invoked on the thread calling start().

It must return promptly, must not throw, and must not call start(), stop(), or destroy this monitor. The application may marshal these progress values to its own UI context.

◆ request_remaining_profiles_when_connected

bool dmn::Dmn_AncsMonitorConfig::request_remaining_profiles_when_connected {}

Request remaining BlueZ profiles for an already-connected target.

This is intended for frontends that require a pre-existing link but need the CLI-equivalent profile completion before ANCS startup. It has no effect unless the selected device is already connected.

◆ require_existing_connection

bool dmn::Dmn_AncsMonitorConfig::require_existing_connection {}

Require the device to already be present, paired, and connected.

When true, startup does not discover, pair, or establish a device connection. Remaining profiles are requested only when request_remaining_profiles_when_connected is enabled.
